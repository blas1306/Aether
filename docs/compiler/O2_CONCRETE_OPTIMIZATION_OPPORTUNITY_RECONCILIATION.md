# O2.12 — Concrete optimization opportunity reconciliation

Status: analysis-only audit; production optimizer behavior is frozen. Exact
counts and sites live in the deterministic companion JSON, regenerated by

## Method

An opportunity is productive only when it names an exact workload, function,
SSA instruction and operands; supplies the complete semantic proof and exact
rewrite/effect; has no blocker; and passes an independent fail-closed verifier.
`UNKNOWN`, incomplete evidence and `HYPOTHESIS_ONLY` never enter the ranking.
Fingerprints use workload, function, opcode, operands and block role, not raw
SSA numbering alone.

The 15-workload production O2 corpus is lowered to measure the instruction,
loop and explicit ARC census. Backend ARC is reconciled independently with the
current ownership audit (69 implicit retains globally, 11 in loops). Expected
explicit reference is 48 retains / 901 releases globally and 11 / 37 in loops;
the JSON remains authoritative as the corpus evolves. Unsupported inputs are
reported separately.

## Findings and ranking

GVN/CSE discovery keys exact pure scalar operations by opcode, type, operands
and semantic fields. It requires dominance, purity and no memory, ownership,
call, trap or exception effect. Same-block and cross-block dominance sites are
reported separately. Memory reads are never assumed pure.

Memory LICM requires invariant operands, preserved locations, alias/mod-ref,
safe preheader execution, trap/exception equivalence, ownership safety and use
dominance. Loop rows record preheader, header, latch, exits, depth, exact IVs,
arithmetic, calls and ARC. Checked arithmetic prevents IV/strength-reduction
qualification without exact trap equivalence.

Allocations are inventoried, but no-escape alone is not sufficient for stack
promotion or elision. A representable stack form, lifetime, destruction and
exception cleanup must be exact. The stable `%373` extraction remains
`ANALYSIS_BLOCKED`: `text.byteSlice` needs a borrow/no-capture argument summary;
inlining is not required. Its theoretical retain/release saving is not counted.
Collection generalization likewise needs an exact get, release, consumers and
owner-lifetime proof. Inlining/devirtualization are examined only as blockers
to an otherwise exact candidate.

The family matrix includes exact static effects, LLVM overlap, complexity,
risk and enabling value. A zero-candidate family cannot win. Scalar CSE already
completed by LLVM is deprioritized unless it enables another Aether pass. If no
eligible family remains, the required decision is
`IMPROVE_OPTIMIZATION_MEASUREMENT_FIRST`; otherwise the report lists the exact
supporting fingerprints and deliberately narrow next milestone.

## Freeze and regression coverage

Tests reject hypothesis-only candidates, missing instructions or transforms,
unknown proofs and known blockers; preserve historical false-copy status;
accept an exact verified site; check deterministic fingerprints; and prevent a
zero-candidate recommendation.

No lifecycle, ownership, ARC, ABI, backend, generated code, BCE, LICM,
LocalARC, OwnershipElidedArrayGet or O0/O1/O2 membership changes. No historical
JSON is modified.
